# 社交渠道

把 DotCraft 接进团队已经在用的聊天工具，同事在群里问一句就能拿到答案，不必打开 Desktop。QQ、企业微信、飞书 / Lark、Telegram 和微信都可以接，聊出来的会话和记忆与工作区的其他入口完全共用。

![DotCraft Desktop 中可用的渠道](https://github.com/DotHarness/resources/raw/master/dotcraft/channels/catalog.png)

## 接入渠道

1. 在 DotCraft Desktop 打开工作区，进入**渠道**。
2. 选择要接入的平台，按表单填写该平台的凭据。
3. 到平台后台或 Bot 工具里完成对应设置。
4. 启用渠道，给 Bot 发一条测试消息。

渠道进程由 Desktop 托管，不用另外部署。每个平台需要哪些凭据，见下表对应的设置页。所有渠道共用的配置项见[渠道配置](../../configuration/channels)。

## 内置渠道

| 平台 | 接入方式 | Agent 能发送的内容 | 工作时的提示 | 设置 |
|---|---|---|---|---|
| **QQ** | NapCat 或 OneBot v11 反向 WebSocket | 文本、图片、文件、语音、视频 | 请求失败时发一条通知 | [QQ 设置](./qq) |
| **企业微信 / WeCom** | 群机器人回调 URL、Token、EncodingAESKey | 文本、图片、文件、语音 | 请求失败时发一条通知 | [企业微信设置](./wecom) |
| **飞书 / Lark** | 启用 Bot 和 WebSocket 事件订阅的自建应用 | 带格式的文本、图片、文件、音频、视频 | reaction、状态卡片 | [飞书设置](./feishu) |
| **Telegram** | BotFather token | 带格式的文本、图片、文件、音频、视频 | 正在输入提示，请求失败时发一条通知 | [Telegram 设置](./telegram) |
| **微信 / Weixin** | 腾讯 iLink 二维码登录 | 文本、图片、文件 | 请求失败时发一条通知 | [微信设置](./weixin) |

## Agent 在聊天里怎么说话

![DotCraft 渠道适配器拓扑](/channel-adapter-topology.svg)

- 发给 Bot 的消息都在同一个会话里。Agent 工作时你再发的消息会并入正在进行的工作，补充细节或改方向都不用等它做完。
- Agent 通过向聊天发送消息来回复：文本，以及平台支持时的图片、文件、语音或视频。聊天里的人只看得到它发出的内容。它的推理、工具调用和过程记录都留在会话里，在 Desktop 中可以看到。
- Agent 知道自己在哪个平台、哪个聊天，也知道这个聊天能显示什么，所以在不支持格式的平台上会写纯文本。
- 让 Agent 发到别处，比如另一个群，它也能发过去。每个新的目的地都会先请求审批。
- 审批和补充提问会直接出现在聊天里，平台有按钮时用按钮。
- Desktop 打开同一个工作区，就能查看这些会话的历史或接着聊。

底层模型见[统一会话核心](../../contribute/architecture/session-core)。

### Agent 工作时

Bot 会用平台允许的方式表明自己在忙。在飞书上，它会给你的消息加一个 reaction，工作超过 20 秒时出现一张状态卡片。卡片静默更新，最后停在已完成、失败或已停止。在 Telegram 上，Bot 会显示正在输入。没有状态卡片的平台上，请求失败时 Bot 会在聊天里发一条简短通知。

## 聊天中的命令

命令单独作为一条消息发送。命令会立即执行，Agent 正在工作时也一样。

| 命令 | 作用 |
|---|---|
| `/new` | 在这个聊天里开一段新会话。之前的会话仍可在 `/sessions` 中找到。 |
| `/stop` | 停止当前的工作。后台任务继续运行。 |
| `/stop all` | 停止当前的工作，丢弃排队的消息，并停止所有后台任务。 |
| `/tasks` | 列出后台任务。`/tasks stop <n>` 停止其中一个。 |
| `/status` | 显示会话在做什么：状态、模型、模式、上下文用量，以及排队或等待审批的内容。 |
| `/model [model]` | 列出可用模型，或把这个会话切换到某个模型。仅限管理员。 |
| `/mode [agent\|plan]` | 显示或切换模式。 |
| `/sessions` | 列出这个聊天最近的会话。 |
| `/resume <n>` | 回到 `/sessions` 里的第 `n` 个会话。 |
| `/compact` | 压缩会话上下文。 |
| `/automate list\|show\|pause\|resume\|run\|remove` | 管理从这个聊天创建的自动化。仅限管理员。 |
| `/help` | 列出你能使用的命令。 |
| `/init` | 创建一个写有 DotCraft 指令的 `AGENTS.md` 文件。仅限管理员。 |
| `/debug` | 开关调试模式。仅限管理员。 |

`/new` 和 `/resume` 会先停止当前的工作，再切换会话。`/compact` 和 `/init` 只在 Agent 空闲时执行，否则 Bot 会回复正忙。Bot 等你回答问题时命令照样可用，`/stop` 不会被当成答案。工作区自己的自定义命令在聊天里同样可用。

命令给出选项时，比如 `/model` 列出的模型，飞书和 Telegram 以按钮显示，其他平台显示带编号的列表，并写出每个选项要发送的命令。Telegram 还会填充命令菜单，每个人只看到自己能用的命令。

用文字回复待处理的审批时，发送 `/approve`，发送 `/approve session` 在本会话剩余时间内允许同类操作，或发送 `/deny`。这些回复只处理你自己的审批，也就是你发起的工作所请求的审批，所以在群里没人能用它们替别人批准。各平台自己的回复关键词和按钮也照常可用。

管理员命令只对渠道管理员列表里的人开放。在[渠道配置](../../configuration/channels)中用 `adminUsers` 设置。列表为空时，聊天里没有人能执行管理员命令。微信没有管理员列表：只有机器人的所有者能联系到它，因此每个微信发送者都能执行管理员命令。

## 从聊天创建的自动化

在聊天里让 Agent 按计划做某件事，它创建的自动化就属于这个聊天。每次运行只在 Agent 有内容要发时才发到聊天里，检查没发现问题就保持安静。运行失败时，Bot 会发一条写明自动化名称的简短通知。用 `/automate` 或 Desktop 的**自动化**页面管理这些自动化。

## 把 Desktop 对话接到聊天里

在 Desktop 对话里输入 `/bind`，选一个已连接的渠道。DotCraft 会给出一条 `/bind 482913` 这样的命令，10 分钟内在目标聊天里发送它。之后那个聊天的消息会进入这个会话，Agent 也会把回复发到那里。

绑定只对那个聊天生效，其他聊天照旧各聊各的。绑定期间，这个聊天固定在该会话上：`/new`、`/sessions` 和 `/resume` 会回复聊天已绑定，不做任何改动。想停止时，在对话的 **⋯** 菜单里选**停止在 … 中继续**，或输入 `/unbind`。

## 开放到群聊之前

把 Bot 放进群聊或公开聊天之前：

- 文件和 Shell 操作保持需要审批。
- 平台支持时，把渠道限制到可信的用户、群或聊天。
- 管理员权限只给应该切换模型或管理自动化的人。
- 自己运行适配器时，给 AppServer WebSocket 设一个强随机 token。
- 平台需要回调 DotCraft 时，生产部署走 HTTPS。

对应的准确字段名见[入口与服务](../../configuration/services)。
