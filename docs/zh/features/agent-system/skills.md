# 技能与自学习

技能把"这件事怎么做"教给 Agent 一次，之后遇到同类任务，它按需加载这份说明照着做。每个技能是一份带 frontmatter 的 Markdown 文件，可以由系统内置，可以你自己写，也可以让 Agent 在任务顺利完成后自己保存下来。

![DotCraft 技能来源总览](/skills-sources-overview.svg)

## 技能从哪里来

| 来源 | 说明 |
|---|---|
| **系统** | DotCraft 自带的内置技能，所有工作区共用 |
| **个人** | 你自己写的通用技能，跨工作区可用 |
| **工作区** | 当前项目专属的技能，跟着仓库走 |
| **插件自带** | 由插件分发，跟着插件一起安装和卸载 |
| **市场安装** | 从 SkillHub、ClawHub 装进来的第三方技能 |

自己写技能时，放在 `~/.craft/skills/` 就是个人技能，放在工作区的 `.craft/skills/` 就是项目技能。所有来源都在技能页面里控制启用状态，从市场搜到的技能要先安装才会进入本地列表。

## 让 Agent 自己沉淀技能

在 Desktop 的 **设置 → 个性化 → 启用自我学习** 打开这项能力，Agent 就能在任务完成后把行之有效的做法写成工作区技能，也能修补已有技能里过期或有坑的步骤。新建技能和破坏性改动都会先向你确认。

它只写当前工作区的技能目录。系统技能和个人技能是只读的，需要改动时，Agent 会先复制一份到工作区再改。开启后 Agent 还会拿到一份内置的写作参考，讲清楚技能怎么组织、附带文件放在哪、常见的坑在哪里。关掉自我学习，这份参考也随之消失。完整的开关和限制见[配置完整参考](../../developing/configuration#workspace-memory-与-skills)。

### 什么值得存成技能

- 复杂任务做完后，总结出一套可以复用的流程
- 修好了一个以后大概率还会再遇到的问题
- 你纠正过 Agent 的做法，而且这个做法稳定下来了
- 用现有技能时发现它的步骤过期、不完整或有坑

一次性的简单问答不必存成技能。

## 搜索与安装

DotCraft 的技能页面同时搜索本地已安装的技能和 SkillHub、ClawHub 两个外部市场。来源筛选（全部 / 系统 / 个人 / 市场）只影响浏览结果，不改变启用状态。

![技能页面](https://github.com/DotHarness/resources/raw/master/dotcraft/skills.png)

从市场装一个技能：

1. 在搜索结果里打开它，读一遍 README、描述和来源链接。
2. 点击 **让 DotCraft 安装**。
3. DotCraft 启动一个安装 Agent，它检查你的工作区、系统环境和可用工具，必要时生成一份适配本地环境的版本。

![技能市场搜索结果](https://github.com/DotHarness/resources/raw/master/dotcraft/skill-hub.png)

<p class="caption">Desktop 通过 DotCraft 安装市场技能并生成本地变体</p>

市场技能装在工作区的 `.craft/skills/` 下，同名技能已经存在时，Desktop 会先让你确认再覆盖。系统技能和插件自带的技能默认可信，SkillHub 和 ClawHub 是外部来源，拿不准的技能先在分支或单独的工作区里试。

### 变体：留住原版，叠加优化

通过 **让 DotCraft 安装** 装进来的技能不会被直接改写。Agent 保留原版，另外生成一份针对当前环境优化的变体，之后优先使用当前生效的那份。想回到市场上的原始内容，在技能详情里点 **恢复源文件**。

![技能变体](https://github.com/DotHarness/resources/raw/master/dotcraft/skill_variant.gif)

自学习带来的优化留了下来，出问题也有一条干净的退路。

## 启用与禁用

技能页面右上角的 **管理** 是批量开关的入口。在里面搜索已安装的技能，用每行的开关控制它是否启用。被禁用的技能不会进入 Agent 的上下文，文件仍然留在磁盘上。

## 官方工作流插件

官方的开发工作流技能按作用域拆成两个插件。`dotcraft` 提供 DotCraft 专属的开发、文档、发布、简化、故障诊断、上下文交接和问题上报流程。`harness-workflow` 提供遵循当前项目约定的功能规划和独立 UI 原型流程。在插件页面按需启用，开发大型 DotCraft 功能时通常两个都开。两者如何划分产品规则与共享工作流，见 [Spec-Driven Development](../../developing/workflow/spec-driven-development)。

## 怎么选

| 场景 | 推荐 |
|---|---|
| 项目内的固定流程（"提交 PR 前必跑 lint 和测试"） | 工作区技能，手写或让 Agent 建 |
| 跨项目通用的偏好（你自己的代码风格） | 个人技能 |
| 想把工具和多个技能打包分发 | 做成[插件](./plugins-tools) |
| 想让 Agent 把刚解决的问题沉淀下来 | 开启自我学习 |
| 想直接用社区已有的方案 | 在技能页面搜市场，再让 DotCraft 安装 |
