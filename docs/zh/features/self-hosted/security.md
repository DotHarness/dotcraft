# 安全

DotCraft 提供文件访问限制、Shell 命令审批和工具能力开关。你可以为工作区配置敏感文件路径、命令规则和可用工具。

## 默认安全基线

新建一个工作区，护栏是这样的：

- 文件工具访问工作区外路径、Shell 从工作区外目录启动时需要审批。
- 强制删除文件或打开网址的 Shell 命令先问再跑。从工作区内启动、没有命中规则的其他命令直接执行。
- 黑名单是空的，你机器上的凭据和密钥目录得自己加。
- 内置工具全部可用，除非你主动收紧。

这几项对应的字段名、默认值和 JSON 示例都在 [Tools 与 Security](../../developing/configuration#tools-与-security)。

## 文件黑名单

黑名单列出文件工具不能访问的路径，对 CLI、Desktop、外部渠道和自动化任务一视同仁。

文件工具读取、写入、编辑、搜索这些路径的操作会被拒绝。黑名单的优先级高于工作区边界的审批，命中的路径不会走审批流程，直接拒绝。写绝对路径或以 `~` 开头的路径都可以，子路径一并覆盖。

## 工作区边界

文件工具检查实际访问的路径是否位于工作区内。Shell 检查调用时指定的启动目录。

文件工具的目标路径或 Shell 的启动目录位于工作区外时，DotCraft 按策略拒绝或发起审批。后续终端输入沿用相同的启动目录作为审批上下文。

## Shell 命令

命令执行前，DotCraft 检查你配置的命令规则、危险操作和启动目录。规则可以放行、询问或拒绝命令，没有匹配规则时，强制删除文件、打开网址或从工作区外启动会触发审批。DotCraft 不认识的 shell 名称会被直接拒绝。命令文本会传给选定的 shell，包括 Windows 的 `/s`、`/t` 等选项。

有些命令会一直运行、等待后续输入，比如交互式 shell 或语言解释器。Agent 往这类终端里输入的内容仍会接受命令规则和危险操作检查。审批使用终端启动时的 shell 和目录作为上下文。

审批面板会显示将要使用的 shell、DotCraft 解读出的命令，以及询问的原因。脚本里有 DotCraft 无法提前读懂的语法时，面板会说明这一点，并把脚本整体展示出来。

每个选项记住的范围不一样：

- **允许**只运行这一次。
- **本会话允许**在这次对话剩余时间里，对同一目录下的同一条命令不再询问。
- **永久允许**会写入一条规则，放行以相同开头词起始的命令。危险命令和读不懂的脚本例外，它们只按原样记住，不会变成规则。

你自己写的规则先于其他检查生效。每条规则给出命令的开头词，并指定放行、询问还是拒绝，比如让 `git push` 总是询问、让 `rm` 一律拒绝。字段格式见 [Tools 与 Security](../../developing/configuration#tools-与-security)。

## 工具能力开关

工具策略决定哪些内置工具对 Agent 可见、文件工具越界访问和 Shell 从工作区外启动是否需要审批、文件和 Web 响应最多返回多少内容，以及是否启用 LSP 工具。需要精确的 allow-list、Web 搜索 provider、超时或输出上限时，在 [Tools 与 Security](../../developing/configuration#tools-与-security) 里查字段。

## Hooks

Hooks 把安全检查变成会话生命周期上的关卡：命令执行前先检查一遍、工具调用后审阅改动，或者在高风险操作前停下来等你点头。概念说明见[生命周期 Hooks](../agent-system/hooks)，事件、matcher 规则和退出码语义见[配置参考](../../developing/configuration#automations-goals-与-hooks)。

写 Hook 时：

- 脚本保持短小，复杂逻辑放进项目自己的脚本。
- 阻塞型 Hook 一定要打印清楚的错误信息，否则你只会看到操作被挡下，不知道为什么。
- 不要把密钥写进 Hook，用环境变量或全局配置。
- 命令路径写成工作区相对路径，不同入口的 cwd 并不一致。

## 严格部署清单

DotCraft 暴露给外部渠道或公网时，这些策略建议一起开：

| 区域 | 建议 |
|---|---|
| 工作区边界 | 文件工具越界访问和 Shell 从工作区外启动需要审批 |
| 黑名单 | 禁止文件工具访问密钥和凭据目录 |
| 工具表面积 | 只保留部署所需工具 |
| AppServer | 远程访问使用强随机 WebSocket token |
| Subagents | 除非明确需要，否则限制递归委派 |

## 使用场景

| 场景 | 推荐 |
|---|---|
| 个人本地项目 | 保留工作区外审批，把 SSH、云凭据、密码管理器目录加入黑名单 |
| 团队共享工作区 | 把安全策略放进工作区 `.craft/config.json`，所有入口统一执行 |
| 外部渠道或 bot | 开启审批，收紧工具，使用强 token |
| 自动化任务 | 按任务配置可用工具和命令规则 |
